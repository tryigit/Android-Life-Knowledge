# UFS Storage Health & Lifecycle

Just like batteries, the flash storage (UFS/eMMC) inside an Android device degrades over time as data is written and erased. The JEDEC standard for Universal Flash Storage defines specific health descriptors that allow the host (Android OS) to query the estimated life remaining of the storage device.

## Accessing UFS Health Data

On many Android devices, the UFS host controller driver exposes these health descriptors via `sysfs`. While the exact path depends on the specific System-on-Chip (SoC) and board configuration, it is typically located within the platform device directory.

**Common Path Example:**
```
/sys/devices/platform/soc/<soc_specific_addr>.ufshc/health_descriptor/
```

*Note: `<soc_specific_addr>` varies (e.g., `1d84000.ufshc` on some Qualcomm platforms).*

## Interpreting Health Values

The health descriptor contains three critical files that provide insight into the storage's lifespan. These values are hex codes that map to percentage ranges or status flags.

### 1. Device Life Time Estimation (Type A & Type B)

Flash memory consists of different blocks (SLC, MLC, TLC). The standard provides two estimation fields, often reflecting different memory types or storage partitions within the UFS device.

*   **File:** `life_time_est_a`
*   **File:** `life_time_est_b`

| Value (Hex) | Life Time Used | Description |
| :--- | :--- | :--- |
| `0x00` | Not Defined | Information not available |
| `0x01` | 0% - 10% | Device is healthy, little wear |
| `0x02` | 10% - 20% | Device is healthy |
| `0x03` | 20% - 30% | Device is healthy |
| `0x04` | 30% - 40% | Moderate usage |
| `0x05` | 40% - 50% | Moderate usage |
| `0x06` | 50% - 60% | Significant usage |
| `0x07` | 60% - 70% | Significant usage |
| `0x08` | 70% - 80% | High usage |
| `0x09` | 80% - 90% | Very high usage |
| `0x0A` | 90% - 100% | Critical usage, near end of life |
| `0x0B` | Exceeded | Maximum estimated life time exceeded |

### 2. Pre-EOL (End of Life) Information

This field provides a simplified status of the device's overall health, specifically regarding reserved blocks used for bad block management.

*   **File:** `pre_eol_info`

| Value (Hex) | Status | Description |
| :--- | :--- | :--- |
| `0x00` | Not Defined | Information not available |
| `0x01` | **Normal** | Device is functioning normally |
| `0x02` | **Warning** | Consumed 80% of reserved blocks. Backup recommended. |
| `0x03` | **Urgent** | Critical state. Device failure imminent. |
| `0x04`+ | Reserved | Reserved for future use |

> [!WARNING]
> If `pre_eol_info` returns `0x02` or `0x03`, immediate data backup is strongly advised. The storage chip may become read-only or fail completely soon.

## Reliability of Data

Unlike battery statistics which can be reset or manipulated by software (to some extent), these UFS health descriptors are generated by the storage controller's firmware based on physical wear leveling data. They represent the **hardware reality** and cannot be reset by wiping the device or flashing a new ROM.
